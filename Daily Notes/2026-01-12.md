### Key Questions to Answer

1. **What does each phase preserve (invariants)?**
   - Lexing: Preserves nothing (first phase, transforms raw characters)
   - Parsing: Preserves token identities and values
   - Semantic Analysis: Preserves syntactic structure
   - IR Translation: Preserves program meaning/semantics
   - Optimization: Preserves program meaning (observable behavior)
   - Code Generation: Preserves program meaning

2. **What is the "contract" between adjacent phases?**
   - Each phase expects specific guarantees from the previous phase and provides new guarantees to the next
   - Lexing: Expects valid encoding → Guarantees well-formed tokens
   - Parsing: Expects valid tokens → Guarantees valid syntax tree
   - Semantics: Expects valid AST → Guarantees type-safe, name-resolved AST
   - IR: Expects resolved AST → Guarantees explicit control flow
   - Optimization: Expects valid IR → Guarantees equivalent but efficient IR
   - Codegen: Expects optimized IR → Guarantees valid machine code

3. **Why can't phases be reordered arbitrarily?**
   - Each phase depends on guarantees established by previous phases
   - Parsing needs tokens because structure depends on symbol boundaries
   - Semantics needs structure because name resolution depends on scope/nesting
   - IR needs meaning because control flow requires knowing what operations do
   - Optimization needs IR to eliminate redundancy
   - Codegen needs optimized IR for register allocation
   - **Key insight:** Skipping a phase doesn't simplify compilation—it makes the next phase impossible

4. **What information flows from one phase to the next?**
   - Lexing → Parsing: Token stream + source locations (for error messages)
   - Parsing → Semantics: AST nodes + token metadata (types, positions)
   - Semantics → IR: Annotated AST + symbol table + type information
   - IR → Optimization: CFG + data flow facts
   - Optimization → Codegen: CFG + liveness info + register hints
   - Codegen → Linker: Object code + symbol tables + relocation info

## Session Notes

### Core Principle: Each Phase Resolves Specific Ambiguity

The fundamental pattern is: **ambiguity → resolution → precision**

Each compiler phase exists specifically to resolve one kind of ambiguity:
- Characters are ambiguous about boundaries → Lexing resolves them
- Tokens are ambiguous about structure → Parsing resolves it
- Structure is ambiguous about meaning → Semantics resolves it
- High-level structure is ambiguous about execution → IR translation resolves it
- IR is ambiguous about efficiency → Optimization resolves it
- IR is ambiguous about target machine → Code generation resolves it

### Example: `x = 3 + 4 * 5` Through the Pipeline

**Lexing:** Resolves character boundaries
- Input: Character stream `x=3+4*5`
- Output: `IDENT(x) EQUALS INT(3) PLUS INT(4) STAR INT(5)`

**Parsing:** Resolves operator precedence
- Input: Token stream
- Output: `Assign(x, Add(Int(3), Mul(Int(4), Int(5))))`
- Clarifies: `3 + (4 * 5)` not `(3 + 4) * 5`

**Semantics:** Resolves names and types
- Checks if `x` is declared, validates types can be added/multiplied
- Output: Annotated tree with type information

**IR Translation:** Makes control flow explicit
- Creates three-address code with explicit evaluation order

**Optimization:** Eliminates inefficiency
- Constant folding: `x = 23` (computes `3 + 20` at compile time)

**Code Generation:** Maps to machine instructions
- Output: `mov dword ptr [rbp-4], 23`

### Why Phase Order Matters

Each phase builds on guarantees from previous phases. The assumptions would break if reordered because:
1. You can't determine structure without knowing symbol boundaries
2. You can't resolve names without knowing scope structure
3. You can't create control flow without knowing operation meanings
4. You can't optimize without explicit IR representation
5. You can't allocate registers without knowing what's live

## Insights

- **Ambiguity is by design**: Source code is intentionally compact and human-friendly, which inherently makes it ambiguous. Compilation is the process of systematically removing this ambiguity.

- **Phases are not arbitrary divisions**: Each phase exists because it resolves a specific, unavoidable ambiguity that the previous representation contains.

- **Invariant preservation is the key to correctness**: Each phase must preserve certain guarantees while transforming others. This contract system ensures correctness.

- **Information never flows backward**: The pipeline is strictly one-directional. Code generation never tells the parser what to do.

- **Skipping phases is impossible, not optional**: Each phase's output is required input for the next. There's no shortcut through compiler phases.
