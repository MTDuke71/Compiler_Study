### Key Questions to Answer

1. Why do we need IR in addition to AST?
   - AST preserves source structure (good for validation, bad for transformation)
   - IR makes control flow explicit (gotos, labels, basic blocks)
   - IR provides uniform representation (all constructs become same primitives)
   - IR enables optimization by making data flow visible

2. What is the difference between three-address code and SSA?
   - **Three-Address Code (TAC):** Each instruction has at most 3 operands (e.g., `t1 = a + b`)
   - **Static Single Assignment (SSA):** Each variable assigned exactly once (enables powerful optimizations)
   - SSA uses phi nodes for merging control flow (will learn in detail Week 9)

3. How does IR make control flow and data flow explicit?
   - Control flow: `while` loops become labeled blocks + conditional jumps
   - Data flow: Each operation is atomic (single assignment per line)
   - Basic blocks show all possible execution paths
   - Makes dependencies between values visible

4. What transformations does IR enable that AST doesn't?
   - Constant folding: `3 + 4` → `7`
   - Dead code elimination: Remove unused assignments
   - Common subexpression elimination: Compute `a + b` once, reuse
   - Loop-invariant code motion: Move unchanging computations outside loops

## Session Notes

### AST vs IR: Different Purposes

**AST is source-oriented:**
- Preserves syntactic structure from source code
- Great for validation (semantic analysis, type checking)
- Too much irrelevant detail for optimization
- Control flow is implicit in tree structure

**IR is machine-oriented:**
- Lowered representation closer to machine code
- Uniform primitives (assignment, jumps, conditionals)
- Control flow is explicit (labels and gotos)
- Designed for transformation and analysis

### The "goto is harmful" paradox

**Mind-blown moment:** goto is bad in human-written code but essential in IR!

- **Source code:** Use `while`, `if`, `for` for human readability
- **IR:** Everything becomes goto because that's how CPUs actually work
- **Insight:** Modern languages hide goto behind structured constructs, but compilers convert back to goto-based control flow
- My C64 BASIC instincts were right for machine-level thinking! 🎮

### IR Forms: TAC and SSA

**Three-Address Code:**
```
t1 = a + b
t2 = t1 * c
x = t2
```
Simple, maps to assembly naturally

**Static Single Assignment (SSA):**
```
t1 = a + b
t2 = t1 * c
x1 = t2
```
Each variable assigned once—enables powerful optimizations
(Will learn phi nodes in Week 9)

## Insights

- IR is the compiler's "working representation"—where all the transformation happens
- AST's job ends after semantic analysis; from IR onward it's all optimization and code generation
- Phases are ordered by dependency: need structure for meaning, need meaning for IR
- Uniformity enables modularity: one optimization can improve all loops/conditionals because they use same IR primitives
- goto isn't evil—it's just the reality of how machines execute code
