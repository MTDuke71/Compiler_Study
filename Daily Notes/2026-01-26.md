## Session Notes

### Parser Responsibilities: Token Stream → AST

The parser sits between lexer and semantic analysis, performing a critical transformation:

**Input:** Linear token stream from lexer (unstructured sequence)
**Output:** Abstract Syntax Tree (hierarchical structure with meaning)

**Key distinction:**
- **Concrete syntax tree (CST):** Preserves every detail from grammar (parentheses, commas, etc.)
- **Abstract syntax tree (AST):** Preserves only semantically relevant structure

**Example:** `3 + 4 * 5`

```
Token stream: [INT(3), PLUS, INT(4), STAR, INT(5), EOF]

AST (preserves precedence):
     +
    / \
   3   *
      / \
     4   5
```

The AST encodes precedence structurally—`*` is deeper in tree, so evaluates first. Parentheses from source are gone; their effect is captured in tree shape.

**Chess analogy:** Like converting algebraic notation (e4, Nf3) into position representation optimized for evaluation. Surface syntax disappears; structure that matters remains.

### Grammar Design Principles for Recursive Descent

Not all grammars work with recursive descent. Two critical transformations:

#### 1. Eliminate Left Recursion

**Problem grammar:**
```
Expr → Expr '+' Term | Term
```

Recursive descent fails: `parseExpr()` immediately calls `parseExpr()` → infinite loop.

**Solution:** Right recursion with tail
```
Expr     → Term ExprTail
ExprTail → '+' Term ExprTail | ε
```

Now `parseExpr()` calls `parseTerm()` first (makes progress), then handles tail recursively.

**Pattern:** `A → Aα | β` becomes `A → βA'` and `A' → αA' | ε`

#### 2. Left Factoring

**Problem grammar:**
```
Stmt → 'if' '(' Expr ')' Block
     | 'if' '(' Expr ')' Block 'else' Block
```

Common prefix `'if' '(' Expr ')' Block` forces parser to look ahead arbitrarily far to choose production.

**Solution:** Factor out common prefix
```
Stmt     → 'if' '(' Expr ')' Block ElsePart
ElsePart → 'else' Block | ε
```

Now parse common part once, then decide on else clause with 1-token lookahead.

**Pattern:** `A → αβ₁ | αβ₂` becomes `A → αA'` and `A' → β₁ | β₂`

### Encoding Precedence via Grammar Stratification

**Key insight:** Deeper in grammar = tighter binding = higher precedence

**Expression grammar (arithmetic):**
```
Expr   → Term ('+' Term | '-' Term)*
Term   → Factor ('*' Factor | '/' Factor)*  
Factor → INT | ID | '(' Expr ')'
```

**Why this works:**
- To parse `3 + 4 * 5`, `Expr` calls `Term`
- `Term` consumes `3`, sees `+` (not `*`), returns
- `Expr` consumes `+`, calls `Term` again
- `Term` now sees `4 * 5`, builds subtree `(* 4 5)`
- Result: `(+ 3 (* 4 5))`

**Grammar structure enforces precedence:**
1. `Factor` (highest) — atoms and parenthesized expressions
2. `Term` — multiplication/division (binds tighter than addition)
3. `Expr` (lowest) — addition/subtraction

**AoC analogy:** Like preprocessing data structure to make algorithm trivial. Grammar does the work; parser just follows structure.

### AST Node Design

**What must AST nodes preserve?**

1. **Semantic content** (not syntactic sugar)
2. **Source location** (for error messages)
3. **Type** (for later phases)
4. **Child relationships** (the structure itself)

**Example AST node definitions:**

```python
# Base class
class ASTNode:
    def __init__(self, line, col):
        self.line = line
        self.col = col

# Expression nodes
class BinaryOp(ASTNode):
    def __init__(self, op, left, right, line, col):
        super().__init__(line, col)
        self.op = op      # '+', '-', '*', '/'
        self.left = left  # ASTNode
        self.right = right # ASTNode

class IntLiteral(ASTNode):
    def __init__(self, value, line, col):
        super().__init__(line, col)
        self.value = value  # int

class Identifier(ASTNode):
    def __init__(self, name, line, col):
        super().__init__(line, col)
        self.name = name  # string

class FunctionCall(ASTNode):
    def __init__(self, name, args, line, col):
        super().__init__(line, col)
        self.name = name  # string
        self.args = args  # list of ASTNode

# Statement nodes
class IfStatement(ASTNode):
    def __init__(self, condition, then_block, else_block, line, col):
        super().__init__(line, col)
        self.condition = condition  # ASTNode (expression)
        self.then_block = then_block  # list of ASTNode
        self.else_block = else_block  # list of ASTNode or None

class ReturnStatement(ASTNode):
    def __init__(self, value, line, col):
        super().__init__(line, col)
        self.value = value  # ASTNode (expression)

# Function declaration
class FunctionDecl(ASTNode):
    def __init__(self, name, params, body, line, col):
        super().__init__(line, col)
        self.name = name    # string
        self.params = params  # list of strings
        self.body = body    # list of ASTNode (statements)
```

**Design decisions:**
- **Flat operator nodes** (not separate classes per operator) — operator is data
- **Source positions everywhere** — critical for error messages
- **Type field placeholder** — semantic analysis will fill this in
- **No syntactic artifacts** — no tokens for parentheses, commas, semicolons (structure encodes relationships)

### Grammar for Simple Expression Language

**Complete grammar (after transformations):**

```
Program    → FuncList
FuncList   → FuncDecl FuncList | ε
FuncDecl   → 'fn' ID '(' ParamList ')' Block
ParamList  → ID ParamTail | ε
ParamTail  → ',' ID ParamTail | ε
Block      → '{' StmtList '}'
StmtList   → Stmt StmtList | ε
Stmt       → IfStmt | WhileStmt | ReturnStmt | ExprStmt
IfStmt     → 'if' '(' Expr ')' Block ElsePart
ElsePart   → 'else' Block | ε
WhileStmt  → 'while' '(' Expr ')' Block
ReturnStmt → 'return' Expr ';'
ExprStmt   → Expr ';'

Expr       → Term ExprTail
ExprTail   → '+' Term ExprTail | '-' Term ExprTail | ε
Term       → Factor TermTail
TermTail   → '*' Factor TermTail | '/' Factor TermTail | ε
Factor     → INT | ID | CallExpr | '(' Expr ')'
CallExpr   → ID '(' ArgList ')'
ArgList    → Expr ArgTail | ε
ArgTail    → ',' Expr ArgTail | ε
```

**Properties:**
- ✅ No left recursion
- ✅ Left-factored where needed
- ✅ Precedence encoded structurally
- ✅ 1-token lookahead sufficient
- ✅ Ready for recursive descent implementation

**Tokens (from Week 4 lexer):**
- Keywords: `fn`, `if`, `else`, `while`, `return`
- Operators: `+`, `-`, `*`, `/`, `=`
- Delimiters: `(`, `)`, `{`, `}`, `,`, `;`
- Literals: `INT`
- Identifiers: `ID`

## Insights

### Grammar Transformations Are One-Time Investments

Like opening book preparation in chess—upfront cost, but makes runtime implementation trivial. Once grammar is suitable for RD, parser code is mechanical translation.

### Structure Encodes Semantics

The **shape** of the AST tree determines evaluation order. Precedence isn't a lookup table—it's the tree topology. This is why "abstract" syntax tree: abstracts away surface syntax, preserves semantic structure.

### Grammar Stratification = Free Precedence Handling

By layering grammar productions (Expr → Term → Factor), precedence falls out automatically. No special cases, no precedence tables. **The grammar does the work.**

**AoC parallel:** Better data structure (stratified grammar) makes algorithm simple (recursive descent).

### Left Recursion vs. Right Recursion

- **Left recursion:** Natural for left-associative operators, but breaks RD
- **Right recursion:** Works with RD, but creates right-associative parse
- **Solution:** Right recursion with manual left-association during AST construction

Tomorrow we'll see this pattern in code.

### AST Design Principles

1. **Preserve semantic info, discard syntactic sugar**
2. **Source locations always** (future-you will thank present-you)
3. **Think about next phases** (what will semantic analysis need?)
4. **Flat when possible** (fewer node types = simpler code)
